From retail brief to buyer review

In my current workflow, an overseas art team assigns and prepares the display request across a 14-hour time difference. Sourcing builds the pricing structure in Excel. I then gather both pieces into a presentation. I chose this project because a first-pass layout and cost estimate would help me move that daily work forward while specialist reviews are pending.

What runs in the browser

How cost inputs change IMU

Initial markup (IMU) is the difference between assumed retail and the chosen cost basis, expressed as a share of retail. Landed cost adds entered logistics or other costs to First Cost. The studio calculates display IMU from total retail and cost dollars for units actually placed; averaging SKU percentages can give a different result.

Try these synthetic USD values for one SKU. Enter zero if there are no additional costs.

Landed cost: $2.35 · First Cost IMU: 59.76% · Landed IMU: 52.72%
See the formulas

Landed cost = First Cost + additional cost. Unit IMU = (assumed unit retail − selected unit cost) ÷ assumed unit retail × 100. Display IMU uses the same formula with total retail and total cost, each summed using actual placed quantities.

What appears in each export?

The buyer HTML can show assumed MSRP and excludes internal costs and profitability. PNG captures the 3D view. The explicitly requested economics CSV and project JSON can contain internal pricing. Uploaded project data is stored locally in the browser.

What testing taught me

Compare the two documented test workflows

Pallet SKU allocation. In the repaired local browser build, switch between uploaded SKUs on Full Pallet Shelf and Stacking Trays. The browser check found that assigned merchandise and counts updated. The stacking tray showed six units of SKU-3 and nine of SKU-2. The repair report records the original blank-preview failure, fit limits, and export retest.

Mixed-SKU economics. In the Phase 3.1 local browser build, apply the synthetic three-SKU catalog and review the landed-cost basis. The verified 20-unit example showed $93.70 retail, $35.50 landed cost, and 62.11% weighted IMU. The economics report records the inputs, comparison calculations, and export checks.

AI suggested building in phases and testing each one before moving on. I asked for an initial batch of 50 test cases and learned that passing automated checks did not guarantee that my own product uploads and SKU assignments would work. When products disappeared, I took screenshots and described where the expected merchandise was missing.

On the two pallet formats, one invalid placement could blank an otherwise usable preview. The repair preserved valid placements and exposed the fit reason where I was editing. Both formats were retested by switching between actual uploaded SKUs. The documented repository snapshot has 68 passing automated tests, including checks for allocation, economics, export privacy, and the pallet regression.

My next testing rule: End every phase with a complete workflow using representative merchandise: upload, assign, check fit in 3D, review economics, then export. Use the result to add regression cases that synthetic inputs missed.

Current status, limits, and next steps

Available now: Nine display formats, SKU placement and fit checks, 3D previews, local economics, and buyer exports. The public repository contains the runnable Phase 3.1 snapshot with the pallet SKU fix.

Use it to review a buyer concept and compare assumptions. Fit checks use entered dimensions and clearances; they do not certify structural safety, manufacturing readiness, or retailer compliance. MSRP-based IMU is an estimate in USD. The prototype does not verify actual retailer costs or selling prices.

Proposed next step: Have a merchandising teammate follow the workflow with a representative sample catalog. Record unclear steps, check the buyer output, and add regression tests for any new failures.
